# Web 缓存

> 参考：Kurose §2.2

**Web 缓存（Web cache）**——也称**代理服务器（proxy server）**——是代表初始 Web 服务器来满足 HTTP 请求的网络实体。Web 缓存有自己的磁盘存储空间，在空间中保存最近请求过的对象的副本。

Web 缓存既是**服务器**（接收来自浏览器的请求并返回响应）也是**客户端**（向初始 Web 服务器发送请求获取未缓存的对象）。

## 工作流程

1. 浏览器建立到 Web 缓存的 TCP 连接，向其发送 HTTP 请求
2. Web 缓存检查本地是否存储了该对象的副本
3. 如果有（**缓存命中**），Web 缓存直接将该对象返回给浏览器
4. 如果没有（**缓存未命中**），Web 缓存向初始 Web 服务器打开 TCP 连接，发送 HTTP 请求，接收对象，在本地存储一份副本，然后将其返回给浏览器

```
缓存命中:
浏览器 ──GET──▶ Web缓存 ──直接返回──▶ 浏览器

缓存未命中:
浏览器 ──GET──▶ Web缓存 ──GET──▶ 初始服务器
                                   │
浏览器 ◀──返回── Web缓存 ◀──返回───┘
                (存储副本)
```

## Web 缓存的好处

Web 缓存在因特网中有两个主要好处：

- **大幅减少客户请求的响应时间**——特别是客户与初始服务器之间的瓶颈带宽有限时。缓存位于靠近客户端的位置，命中时避免了跨越整个因特网的往返
- **大幅减少机构接入链路到因特网的流量**——通过从缓存提供对象而无需从初始服务器反复获取，节省了带宽成本。例如一所大学的 10 Gbps 接入链路中，缓存可能减少 40–60% 的外部 HTTP 流量

### 缓存部署

CDN（内容分发网络）在因特网上广泛部署缓存服务器。CDN 公司（如 Akamai、Cloudflare）在全球安装大量分布式缓存，将内容从最近缓存提供给用户——参见 [[视频流与CDN]]。

## 条件 GET

缓存中存储的对象可能是**陈旧（stale）**的——Web 缓存需要一种机制来验证其副本是否是最新版本。这是通过**条件 GET（conditional GET）**实现的。

条件 GET 报文使用 GET 方法并且包含 **`If-Modified-Since:`** 首部行：

```
GET /fruit/kiwi.gif HTTP/1.1
Host: www.exotiquecuisine.com
If-Modified-Since: Wed, 9 Sep 2015 09:23:24
```

服务器检查指定对象自该日期以来是否被修改：
- **如果未被修改**：服务器返回 **304 Not Modified** 响应（空实体主体）。304 响应告知缓存它的副本仍然是最新的
- **如果已被修改**：服务器返回 **200 OK** 响应（包含新的对象副本）

```
客户端 ──GET──────────▶ Web缓存
         If-Modified-Since: <date>
                          Web缓存 ──GET──────────▶ 初始服务器
                                   If-Modified-Since: <date>
                          Web缓存 ◀──304 Not Modified──  (对象未变)
客户端 ◀──304 Not Modified──
         (使用缓存中的副本)
```

条件 GET 允许 Web 缓存用极少的网络开销（首部交换，无数据传输）验证其缓存仍然有效，从而同时实现**低延迟**和**信息的新鲜性**。
