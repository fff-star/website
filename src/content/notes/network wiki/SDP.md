# SDP（会话描述协议）

> 参考：RFC 4566; Kurose §9.4.2

**SDP（Session Description Protocol，会话描述协议）**是描述多媒体会话参数的文本格式标准（RFC 4566）。SDP 不是一个传输协议——它是**描述数据的格式**，由其他信令协议（如 [[SIP]]、RTSP）承载在其消息体中使用。SDP 描述的内容包括：媒体类型、传输协议、编码格式、IP 地址和端口号等，使通信双方能够协商出一组共同支持的媒体参数。

## 为什么需要 SDP

在多媒体的会话建立阶段，呼叫方和被叫方需要回答几个关键问题：

1. 对方支持哪些**媒体类型**？（纯音频？音频+视频？）
2. 对方支持哪些**编码格式**？（PCM μ-law？G.729？H.264？）
3. 对方在哪个**IP 地址和端口**上接收媒体流？
4. 对方的媒体接收能力（如最大带宽）是多少？

SDP 为这些问题提供了统一、可读的文本描述格式。它被设计为可扩展——新的媒体类型和编码格式可以自然加入。

## SDP 消息结构

SDP 消息由一行或多行 `type=value` 文本组成，每行以一个单字母的类型字符开头（区分大小写），后跟 `=` 和对应的值。

一个典型的 SDP 描述（携带在 SIP INVITE 消息体中）：

```
v=0
o=alice 2890844526 2890844526 IN IP4 192.168.1.100
s=Call from Alice
c=IN IP4 192.168.1.100
t=0 0
m=audio 49170 RTP/AVP 0 8 18
a=rtpmap:0 PCMU/8000
a=rtpmap:8 PCMA/8000
a=rtpmap:18 G729/8000
m=video 51372 RTP/AVP 31 34
a=rtpmap:31 H261/90000
a=rtpmap:34 H263/90000
```

## 关键字段

| 字段 | 含义 |
|------|------|
| `v=` | 协议版本（当前为 0） |
| `o=` | 会话发起者（用户名、会话 ID、版本号、网络类型、地址类型、地址） |
| `s=` | 会话名称 |
| `c=` | 连接信息（网络类型、地址类型、连接地址）——媒体流应发往的 IP 地址 |
| `t=` | 会话起止时间（`0 0` 表示无限制） |
| `m=` | 媒体描述（媒体类型、端口、传输协议、编码格式列表）——最重要字段 |
| `a=` | 属性行——为前面的 `m=` 或整个会话提供附加信息 |

### 媒体描述行（m=）

格式：`m=<媒体类型> <端口> <传输协议> <编码格式列表>`

- **媒体类型**：`audio`、`video`、`application`、`text` 等
- **端口**：媒体流应发往的传输端口
- **传输协议**：通常为 `RTP/AVP`（RTP Profile for Audio and Video）
- **编码格式列表**：编码格式的 RTP 有效载荷类型编号（整数），按优先顺序排列

### 属性行（a=）

两种形式：
- **属性:值**：`a=rtpmap:<payload type> <编码名>/<时钟速率>` —— 将 `m=` 行中的数字编码格式映射到具体编码名
- **标志**：`a=recvonly`、`a=sendrecv` 等指示媒体方向

## SDP 协商过程

SIP 使用**提供/应答（Offer/Answer）**模型进行 SDP 协商（RFC 3264）：

1. **Offer**（提供）：呼叫方（Alice）在 INVITE 请求中携带自己的 SDP，列出她**支持的所有**媒体类型和编码格式
2. **Answer**（应答）：被叫方（Bob）在 `200 OK` 响应中携带自己的 SDP，从 Alice 的列表中**选择**他支持的选项
3. **媒体流开始**：双方按协商结果配置编码器和 RTP 会话

被叫方的 SDP 还提供**自己接收媒体的 IP 地址和端口**——双方使用对方的 `c=` 和 `m=` 字段中的地址和端口号发送媒体流。

## SDP 与 SIP、RTP 的关系

```
Alice 的 SIP UA          Bob 的 SIP UA
     |                       |
     |── SIP INVITE ────────→|  消息体含 SDP Offer（Alice 编解码能力）
     |                       |
     |←── SIP 200 OK ────────|  消息体含 SDP Answer（Bob 编解码选择+端口）
     |                       |
     |══════ RTP 媒体流 ═════|  按 SDP 协商结果发送（UDP，直连）
```

SDP 是"描述"，SIP 是"信令"，RTP 是"传输"——三者各有分工，组合构成 VoIP/视频会议系统的控制平面和数据平面。
