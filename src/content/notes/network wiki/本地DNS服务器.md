# 本地 DNS 服务器

> 参考：Kurose §2.4

**本地 DNS 服务器（local DNS server）**，也称为**默认名称服务器（default name server）**，是 DNS 解析过程中最靠近用户主机的服务器。每个 ISP 通常维护自己的本地 DNS 服务器，在 DNS 层次结构中充当用户主机与上层 DNS 服务器之间的**代理（proxy）**。

本地 DNS 服务器不属于 [[DNS]] 三层层次结构（根/TLD/权威）中的任何一层，但它是 DNS 解析过程中不可或缺的组成部分。当用户主机发起 DNS 查询时，查询首先到达本地 DNS 服务器，由它完成后续的全部迭代查询或部分递归查询。

## 配置方式

当主机通过 [[DHCP]] 连接到 ISP 时，ISP 除了分配 IP 地址，还会分配一个或多个本地 DNS 服务器的 IP 地址。在 Linux 系统中，这些地址存储在 `/etc/resolv.conf` 文件中，以 `nameserver` 指令的形式记录：

```
nameserver 192.168.1.1
nameserver 8.8.8.8
```

主机也可以手动配置本地 DNS 服务器的地址，例如直接使用公共 DNS 服务替代 ISP 默认提供的服务器。

## 查询过程

本地 DNS 服务器收到主机查询后，执行以下工作链：

1. **检查缓存**：首先检查本地缓存中是否已有被查询域名的记录。如果有且未过期，直接返回给主机。
2. **逐级迭代查询**：若缓存未命中，从根 DNS 服务器开始，依次经过 TLD 服务器、权威 DNS 服务器，逐级获得下一步要查询的服务器地址，直至获得最终结果。
3. **返回结果并缓存**：将结果返回给主机，同时将记录缓存到本地，供后续查询使用。

### 递归查询与迭代查询

从主机的视角看，向本地 DNS 服务器发起的查询通常被配置为**递归查询（recursive query）**——主机要求本地 DNS 服务器完整地解析域名并返回最终结果。

从本地 DNS 服务器的视角看，它向根、TLD、权威服务器发起的查询通常是**迭代查询（iterative query）**——被查询的服务器返回下一级服务器的地址（NS 记录 + A 记录），而非自己代为查询。

```
递归查询（主机 → 本地 DNS 服务器）："请帮我查 www.example.com 的 IP"
迭代查询（本地 DNS 服务器 → 根/TLD/权威）："你知道 www.example.com 的 IP 吗？"
  → "不知道，但 .com TLD 服务器在这里，你自己去问"
```

这一分工设计使根和 TLD 服务器只需处理简单的迭代请求，不必维护大量并发连接的中间状态，而本地 DNS 服务器承担了逐级追踪的复杂性。

## DNS 缓存

[[DNS#DNS 缓存|DNS 缓存]]是本地 DNS 服务器最核心的功能之一。缓存机制大幅减少了 DNS 查询的流量、延迟和上层服务器的负载。

### 缓存策略

- 本地 DNS 服务器收到任何 DNS 应答后，将应答中的资源记录（RR）存储在本地内存中。
- 每条缓存记录有一个**生存时间（Time to Live, TTL）**，由权威 DNS 服务器在 RR 中设定，通常为两天。TTL 过期后记录被删除。
- 本地 DNS 服务器也可以缓存 TLD 服务器的地址，从而在后续查询中跳过根服务器步骤。

### 负缓存

除了成功的解析结果，本地 DNS 服务器还会缓存**否定应答（NXDOMAIN）**——即某域名不存在的结论。NXDOMAIN 的缓存 TTL 由该域权威服务器的 SOA 记录中的 **Minimum TTL** 字段确定。负缓存防止对不存在域名的重复查询穿透到上层服务器。

### 缓存效应举例

假设某本地 DNS 服务器下连接了 500 台主机。第一台主机查询 `www.example.com` 需要经过根 → TLD → 权威的完整查询链（三次迭代）。由于结果被缓存，其余 499 台主机对同一域名的查询将由本地 DNS 服务器直接从缓存中响应，无需任何外部查询。

## 公共 DNS 服务

除了 ISP 提供的本地 DNS 服务器，用户可以选择使用**公共 DNS 服务**作为替代：

| 服务 | IP 地址 | 特点 |
|------|---------|------|
| Google Public DNS | `8.8.8.8`, `8.8.4.4` | 支持 DoT/DoH，全球任播 |
| Cloudflare | `1.1.1.1`, `1.0.0.1` | 隐私导向，不记录查询日志，WARP VPN 集成 |
| Quad9 | `9.9.9.9` | 集成威胁情报，自动屏蔽已知恶意域名 |
| OpenDNS | `208.67.222.222` | 家庭/企业过滤功能，Cisco 旗下 |

使用公共 DNS 的优势包括更快的响应速度（得益于更大的缓存池和广泛的任播部署）、更好的隐私保护（不向 ISP 暴露查询日志）以及额外的安全功能（恶意域名过滤）。其代价是可能绕过 ISP 内部优化（如 CDN 重定向到本地节点）和失去某些企业网络的管理控制。

## 加密 DNS 对本地 DNS 服务器的影响

传统 DNS 查询以明文形式在 UDP 上传输。这意味着 ISP 的本地 DNS 服务器——或者任何能嗅探网络分组的中间人——可以完整地窥探用户的所有 DNS 查询，从而获知用户访问的每一个网站。

加密 DNS（[[DNS#DNS 隐私与安全扩展|DoT 与 DoH]]）改变了这一格局：

- **DoT（DNS over TLS）**：DNS 查询封装在 TLS 连接中（TCP 853），网络层面可见存在 DNS 连接但内容加密。
- **DoH（DNS over HTTPS）**：DNS 查询封装在 HTTPS 请求中（TCP 443），与普通 Web 流量混合，难以被单独识别和阻断。

当用户使用 DoH/DoT 且目标不是 ISP 的本地 DNS 服务器（如直接使用 `1.1.1.1` 的加密解析）时，ISP 的本地 DNS 服务器完全被绕过。这引发了持续的争议：隐私保护方视其为进步，但企业网络管理和传统 DNS 的分层缓存架构却因此受到影响。
