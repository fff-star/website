# 网络管理与 SNMP

> 参考：Kurose §5.7

网络管理包括部署、集成和协调硬件、软件及人力元素，以监视、测试、轮询、配置、分析、评估和控制网络及元素资源，满足实时运营性能和服务质量要求。本节聚焦网络管理的**架构、协议和信息库**基础。

## 网络管理框架

网络管理框架的关键组件：

**管理服务器（Managing Server）**：运行在网络运营中心（NOC）的集中式网络管理工作站中的应用程序。它是网络管理活动的枢纽——控制网络管理信息的收集、处理、分析和/或显示，并在此发起控制网络行为的动作。

**被管理设备（Managed Device）**：受管理网络上的一段网络设备（包括其软件），如主机、路由器、交换机、中间盒等。被管理设备内可能有多个**被管理对象（Managed Objects）**——设备内的实际硬件组件及其配置参数。

**管理信息库（MIB, Management Information Base）**：与被管理设备中每个被管理对象相关的信息被收集到 MIB 中。MIB 对象可能是计数器（如因 IP 首部错误被丢弃的 IP 数据报数）、描述性信息（如 DNS 服务器上运行的软件版本）、状态信息（如特定设备是否正常运行）或协议特定信息（如到目的地的路由路径）。MIB 对象使用 **SMI（Structure of Management Information）**语言定义。SMI 将对象组织在**全局 OID 树（Object Identifier Tree）**中，每个对象有一个数字标识符路径（如 `1.3.6.1.2.1` 代表 MIB-2）。**MIB-2（RFC 1213）**是 SNMP 管理的核心 MIB 模块，包含系统（system）、接口（interfaces）、地址转换（at）、IP、ICMP、TCP、UDP 等约 171 个对象。截至 2015 年，RFC 定义了近 400 个 MIB 模块。

**网络管理代理（Network Management Agent）**：运行在被管理设备中的进程，与管理服务器通信，在管理服务器的命令和控制下对本地设备执行操作。

**网络管理协议**：运行在管理服务器和被管理设备之间，允许管理服务器**查询**设备状态并间接通过代理在设备上执行操作。代理可以使用该协议通知管理服务器**异常事件**（如组件故障或性能阈值违规）。网络管理协议本身**不管理网络**——它提供网络管理员可以用来管理网络的能力。

## SNMP

**简单网络管理协议版本 2（SNMPv2）**是一个**应用层协议**，用于在管理服务器和代理之间传递网络管理控制和信息消息。

### SNMP 的两种使用模式

1. **请求-响应模式**：管理服务器向代理发送请求，代理执行某动作并发送应答。典型地，请求用于**查询**（检索）或**修改**（设置）与受管设备关联的 MIB 对象值
2. **陷阱模式**：代理未经请求向管理服务器发送**陷阱（trap）消息**，用于通知异常情况（如链路接口上/下、相邻路由器丢失、认证失败事件）

### SNMPv2 PDU 类型

| PDU 类型 | 发送方→接收方 | 描述 |
|---------|-------------|------|
| GetRequest | 管理器→代理 | 获取一个或多个 MIB 对象实例的值 |
| GetNextRequest | 管理器→代理 | 获取列表或表中**下一个** MIB 对象实例的值 |
| GetBulkRequest | 管理器→代理 | 获取大数据块中的值（避免多个 GetRequest 的开销） |
| SetRequest | 管理器→代理 | 设置一个或多个 MIB 对象实例的值 |
| Response | 代理→管理器 | 对上述请求或 InformRequest 的响应 |
| InformRequest | 管理器→管理器 | 通知远程管理实体对端 MIB 值 |
| SNMPv2-Trap | 代理→管理器 | 通知管理器异常事件 |

### SNMP 的运输协议

虽然 SNMP PDU 可以通过多种运输协议承载，但 SNMP PDU 通常承载在 **UDP 数据报**的有效载荷中。RFC 3417 声明 UDP 是"首选的传输映射"。由于 UDP 不可靠，请求 ID 字段用于检测丢失的请求或应答。SNMP 标准本身不强制特定重传策略——仅要求管理服务器"在重传的频率和持续时间方面需负责任地行动"。

### SNMPv3

SNMPv3 可视为 **SNMPv2 + 附加安全和管理能力**，特别在管理和安全领域取得了显著变化。SNMPv1 和 SNMPv2 的安全机制极其薄弱：SNMPv1 使用**社区字符串（community string）**作为密码，在网络上明文传输，极易被嗅探。由于缺乏足够的安全性，SNMP 在早期版本中主要用于**监视**而非**控制**（例如 SetRequest 在 SNMPv1 中很少使用）。SNMPv3 引入了基于用户的安全模型（USM），提供认证、加密和访问控制。
