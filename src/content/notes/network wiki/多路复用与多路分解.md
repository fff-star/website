# 多路复用与多路分解

> 参考：Kurose §3.2

多路复用与多路分解是运输层最基础的功能——将主机到主机的交付扩展为进程到进程的交付。

## 基本概念

运输层从网络层接收数据（报文段），将其中的数据传输到正确的应用进程。这一过程中涉及两个方向的操作：

- **多路分解（Demultiplexing）**：在接收端，运输层检查报文段中的字段，确定接收方套接字，然后将报文段交付到正确的应用进程。这是将运输层报文段中的数据**分发**到正确的套接字的过程。
- **多路复用（Multiplexing）**：在发送端，运输层从不同套接字收集数据块，为每个数据块封装上运输层首部（以便后续用于多路分解），然后将这些报文段传递到网络层。这是将不同应用进程的数据**汇集**成报文段的过程。

类比之前"两家各 12 个孩子"的例子：Ann 每天早上将来信分发给对应的孩子就是多路分解；Ann 晚上收集所有要寄出的信交给邮政人员就是多路复用。

## 端口号

多路分解的核心机制是**端口号（port number）**。每个运输层报文段包含一个**源端口号字段**和**目的端口号字段**。接收端的运输层使用目的端口号将报文段交付到正确的套接字。

端口号是一个 16 比特的数，范围 0–65535：

| 范围 | 类型 | 说明 |
|------|------|------|
| 0 – 1023 | **知名端口号（Well-known）** | 由 IANA 固定分配给知名应用协议（HTTP=80, SMTP=25, DNS=53, FTP=21） |
| 1024 – 49151 | 注册端口号 | 由应用开发者向 IANA 注册 |
| 49152 – 65535 | 动态或私有端口号 | 客户端程序自动分配，临时使用 |

## UDP 多路分解

在 UDP 中，一个 UDP 套接字由 **(目的 IP 地址, 目的端口号)** 的二元组完全标识。关键点：**所有具有相同目的 IP 和目的端口的 UDP 报文段——无论其源 IP 和源端口是什么——都被交付到同一个 UDP 套接字**。换句话说，UDP 套接字不区分发送方，只要目的地址和端口相同，数据都到达同一个套接字。服务器只需创建一个 UDP 套接字即可为所有客户端提供服务。

## TCP 多路分解

TCP 的多路分解比 UDP 更复杂。一个 TCP 套接字由 **四元组**完全标识：

$$(\text{源IP地址}, \text{源端口号}, \text{目的IP地址}, \text{目的端口号})$$

这意味着**每个 TCP 连接有自己独立的套接字**。服务器为每个客户端连接创建一个新的套接字——两个具有不同源 IP 或源端口的 TCP 报文段（即使目的 IP 和端口相同）将被交付到不同的套接字。

TCP 服务器的工作方式：
1. 服务器有一个**欢迎套接字（welcome socket）**，在端口 80（例如）上等待来自 TCP 客户端的连接建立请求
2. 当客户端发起 TCP 连接时，欢迎套接字通过 `accept()` 为这个特定的连接创建一个**新的连接套接字**
3. 新套接字由四元组标识，与欢迎套接字不同
4. 服务器的主线程回到欢迎套接字上等待下一个连接请求
5. 每个连接由一个独立的套接字处理，通常由一个独立的线程服务

这种设计使得高性能 Web 服务器可以同时为大量客户端提供并发服务。
