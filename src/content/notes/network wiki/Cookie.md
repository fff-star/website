# Cookie

> 参考：Kurose §2.2

HTTP 服务器是**无状态（stateless）**的——每个请求-响应对都是独立的，服务器不存储关于客户端的任何信息。但 Web 站点通常希望识别用户——无论是限制用户访问还是将内容与用户身份关联。**Cookie**（由 RFC 6265 定义）允许站点跟踪用户。

## Cookie 技术的四个组件

1. 在 HTTP **响应报文**中的一个 Cookie 首部行：`Set-Cookie: 1678`
2. 在 HTTP **请求报文**中的一个 Cookie 首部行：`Cookie: 1678`
3. 在**用户端系统**中保留的一个 **Cookie 文件**，由用户的浏览器管理
4. 位于 **Web 站点的后端数据库**——将 Cookie 标识号与用户数据关联

## Cookie 工作流程

以用户首次访问 Amazon 为例：

```
1. 首次请求
   客户端 ──GET /index.html──▶ 服务器
                                服务器创建标识号 1678
                                后端数据库创建条目 #1678
   客户端 ◀──HTTP 200 OK────
             Set-Cookie: 1678

2. 浏览器存储
   浏览器将 "amazon.com  1678" 写入 Cookie 文件

3. 后续请求（自动携带）
   客户端 ──GET /cart──▶     服务器
             Cookie: 1678
                                服务器查询数据库 #1678
                                识别用户，返回个性化内容
   客户端 ◀──HTTP 200 OK────
```

此后用户的每次 HTTP 请求都会**自动**包含 `Cookie: 1678`。Amazon 服务器据此跟踪用户 1678 在站点的活动。

## Cookie 的应用场景

- **购物车**：用户未登录时即可添加物品到购物车
- **推荐系统**：根据浏览历史推荐商品
- **用户认证**：用户注册后，Amazon 将姓名、电子邮件、地址、信用卡信息与标识号 1678 关联
- **会话管理**：Web 电子邮件服务（如 Gmail）使用 Cookie 维持登录状态
- **一键购物**：已登录用户的支付信息与 Cookie 关联，实现快速结账

## Cookie 与隐私

Cookie 允许站点了解用户的大量信息——用户访问了哪些页面、在哪些页面上停留了多长时间、点击了哪些链接。站点还可以与第三方广告网络合作使用**第三方 Cookie** 跨站点跟踪用户行为，用于定向广告投放。这引发了持续的隐私争议，许多浏览器现在默认阻止第三方 Cookie。
