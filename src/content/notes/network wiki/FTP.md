# FTP

> 参考：Kurose §2.3.5

**文件传输协议（File Transfer Protocol, FTP）**是另一种经典的应用层协议，专门用于在主机之间传输文件。FTP 由 RFC 959 定义，使用 TCP 作为运输层协议。与 HTTP 不同，FTP 的设计存在几个独特的架构决策——最显著的是它使用**两条并行的 TCP 连接**。

## FTP 的双连接架构

FTP 使用两条并行的 TCP 连接，将控制信令与数据传输分离：

| 连接类型 | 端口 | 方向 | 用途 | 生命周期 |
|---------|------|------|------|---------|
| **控制连接（Control Connection）** | 21（服务器端） | 客户端 → 服务器 | 发送命令和接收响应 | 贯穿整个会话 |
| **数据连接（Data Connection）** | 20（服务器端，主动模式） | 服务器 → 客户端（或反向） | 实际传输文件数据 | 每传输一个文件重新建立 |

当用户启动 FTP 会话时，客户端首先与服务器的 21 号端口建立**控制连接**（TCP）。FTP 的命令（如 `USER`、`PASS`、`LIST`、`RETR`）和服务器响应（如 `331 Username OK`）均通过此连接传输。控制连接在整个用户会话期间保持活跃。

当需要传输文件（上传或下载）或列出目录时，FTP 建立第二条独立的**数据连接**。文件传输完毕后数据连接关闭；若需传输另一个文件，则再次建立新的数据连接。由于数据连接在每次文件传输中建立和拆除，FTP 的数据连接是**非持久**的。

## 控制连接：带外信令

FTP 的"控制与数据分离"被称为**带外（out-of-band）**信令——控制信息通过独立的连接发送，与数据通道物理分离。

**与 HTTP 的对比**：HTTP 使用**带内（in-band）**信令——请求行和首部行与数据在同一个 TCP 连接上发送。HTTP 的"带内"设计更简单，但 FTP 的"带外"设计允许在文件传输期间仍然通过控制连接发送控制命令（如中止传输）。

FTP 服务器在控制连接上维护**状态信息**——特别是用户的当前身份（登录用户名）和用户的**当前远程目录**。这意味着 FTP 是**有状态**协议：
- 服务器跟踪用户的当前目录
- 必须对用户会话的持续状态进行维护
- 限制同时活跃的会话数

这与 HTTP（无状态协议——每个请求独立，不保留上一请求的记忆）形成鲜明对比。

## FTP 命令与响应

所有 FTP 命令和响应都通过控制连接以 **7 位 ASCII 格式**发送。每个命令后跟回车换行（CRLF），由 3–4 个大写 ASCII 字符组成（可后跟可选参数），如 USER、PASS（4 字符）和 PWD、CWD（3 字符）。

### 常见 FTP 命令

| 命令 | 全称 | 用途 |
|------|------|------|
| USER | username | 向服务器发送用户名 |
| PASS | password | 发送密码 |
| LIST | list | 请求服务器发送当前远程目录中的文件列表；通过（新建的）数据连接发送 |
| RETR | retrieve | 从远程主机的当前目录中获取（下载）一个文件 |
| STOR | store | 向远程主机的当前目录存储（上传）一个文件 |
| QUIT | quit | 关闭控制连接（结束会话） |
| PWD | print working directory | 显示当前远程目录路径 |
| CWD | change working directory | 改变远程目录 |
| PASV | passive | 请求服务器进入被动模式（服务器监听数据连接） |
| TYPE | representation type | 指定文件的表示类型（A=ASCII, I=Image/Binary 等） |
| MODE | transfer mode | 指定传输模式（S=Stream, B=Block, C=Compressed） |
| STRU | file structure | 指定文件结构（F=File, R=Record, P=Page） |

### 常见 FTP 响应

服务器对每个命令返回响应，包含三位状态码和可选的文本说明：

| 状态码 | 含义 |
|--------|------|
| 331 | Username OK, password required |
| 125 | Data connection already open; transfer starting |
| 226 | Closing data connection; file transfer successful |
| 550 | Requested action not taken (文件不可用等) |

## 表示类型与格式控制

FTP 通过 `TYPE`、`MODE`、`STRU` 三个命令**允许客户端指定传输文件的类型与格式**。这三个命令均在文件传输之前通过控制连接发送，服务器根据这些参数决定如何解释和传输数据。

### TYPE — 表示类型

指定文件的**字符编码和字节表示**方式。这是日常使用中最常需要关注的命令。

| TYPE | 全称 | 说明 |
|------|------|------|
| `TYPE A` | ASCII | 数据以 7 位 ASCII 文本传输；接收端自动将行尾转换为本地操作系统的约定（Unix 用 LF，Windows 用 CRLF） |
| `TYPE E` | EBCDIC | 用于 IBM 大型机之间的文本传输（极少使用） |
| `TYPE I` | Image / Binary | 原始字节流，不做任何转换；适合图片、可执行文件、压缩包、PDF 等所有非文本文件 |
| `TYPE L <n>` | Local | 以 `n` 位字节传输，用于两台非 ASCII 主机间的二进制数据传输（不依赖 8 位字节的系统） |

> **关键陷阱**：FTP 的**默认表示类型是 ASCII（TYPE A）**。如果客户端忘记在执行 `RETR`（下载）或 `STOR`（上传）前发出 `TYPE I`，所有非文本文件都会因为行尾转换（LF ↔ CRLF）而被损坏。因此，**传输二进制文件之前必须切换到 TYPE I**，这是 FTP 使用中最常见的错误来源。

### MODE — 传输模式

指定数据在数据连接上的**传输方式**，影响错误恢复和数据分块。

| MODE | 全称 | 说明 |
|------|------|------|
| `MODE S` | Stream | **默认值。** 数据作为连续字节流传输，无任何结构标记。文件结束由数据连接关闭指示 |
| `MODE B` | Block | 数据被分割为多个数据块，每块带有头部（描述符、字节计数），支持错误恢复和重传单个块 |
| `MODE C` | Compressed | 数据经运行长度编码（run-length encoding）压缩后传输，可减少冗余数据的传输量 |

实际网络中几乎总是使用 MODE S。

### STRU — 文件结构

指定被传输**文件的内部组织形式**。

| STRU | 全称 | 说明 |
|------|------|------|
| `STRU F` | File | **默认值。** 文件是无内部结构的连续字节序列，适用于所有普通文件 |
| `STRU R` | Record | 文件由定长或变长记录组成，仅与文本文件配合使用（用于非 Unix 系统间的记录型文件系统） |
| `STRU P` | Page | 文件由带页码的独立页面组成，支持随机访问，极少使用 |

> 实际使用中，绝大多数 FTP 传输使用 TYPE I + MODE S + STRU F 或 TYPE A + MODE S + STRU F 的组合。TYPE 的选择（ASCII vs Binary）是唯一需要使用者主动关注的参数。

## 主动模式与被动模式

FTP 数据连接的建立方式有两种模式，这一区别对 [[NAT]] 穿越至关重要：

### 主动模式（Active Mode / PORT）

1. 客户端通过控制连接发送 `PORT` 命令，告知服务器客户端正在监听的临时端口号
2. 服务器从端口 **20** 主动向客户端的临时端口发起 TCP 连接
3. 在此 TCP 连接（数据连接）上传输文件

**问题**：许多家庭/企业网络中存在防火墙，阻止从外部发起的 TCP 连接到达内部主机。主动模式下，服务器的连接请求会被客户端防火墙阻挡。

### 被动模式（Passive Mode / PASV）

1. 客户端通过控制连接发送 `PASV` 命令
2. 服务器开启一个临时端口，将端口号通过控制连接返回给客户端
3. 客户端主动向服务器的临时端口发起 TCP 数据连接

被动模式解决了防火墙问题——所有连接均由客户端发起（先建立到 21 的控制连接，再建立到临时端口的数据连接），不会被客户端防火墙阻挡。现代 FTP 客户端普遍优先使用被动模式。

## HTTP 与 FTP 的对比

|          | HTTP                                      | FTP                                 |
| -------- | ----------------------------------------- | ----------------------------------- |
| **运输协议** | TCP                                       | TCP                                 |
| **默认端口** | 80 (HTTP/1.x), 443 (HTTPS)                | 21（控制）, 20（数据）                      |
| **连接模型** | 带内信令（控制与数据在同一连接）                          | 带外信令（控制与数据分离）                       |
| **状态**   | 无状态（每个请求独立）                               | 有状态（维护会话信息）                         |
| **持久连接** | HTTP/1.1 支持持久连接                           | 数据连接非持久（每文件重建）                      |
| **数据传输** | 支持文本和二进制（Content-Type 标识）                 | 默认 ASCII 模式（TYPE A），需手动切换至二进制模式（TYPE I） |
| **用户认证** | 可选（通过 Authorization 首部，通常由应用层实现登录页面）      | 强制用户认证（USER/PASS）                   |
| **标准文档** | RFC 1945 (HTTP/1.0), 7230–7235 (HTTP/1.1) | RFC 959                             |
| **主要用途** | Web 页面、API、流媒体                            | 文件上传/下载、网站维护                        |
| **匿名访问** | 不适用                                       | 支持匿名 FTP（用户名 `anonymous`，密码为电子邮件地址） |
