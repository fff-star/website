# 计算机网络安全概述

> 参考：Kurose §1.6, §8.1

因特网最初的设计主要面向相互信任的用户群体（研究人员）在透明的环境中协同工作。在这种环境中，安全性并不是设计重点。但随着因特网发展成为覆盖全球的公共基础设施，各种安全威胁也随之而来。本章对计算机网络中的安全威胁和防御措施进行概述，第 8 章展开详细内容。

## 安全通信的四要素

§8.1 将安全通信的需求归纳为四个要素（Alice 向 Bob 安全通信的场景）：

| 要素 | 含义 | 详细章节 |
|------|------|---------|
| **机密性（Confidentiality）** | 只有发送方和预期接收方能够理解传输的消息内容，即使消息被截获也无法解读 | [[对称密钥密码学]]、[[公开密钥密码学]] |
| **消息完整性（Message Integrity）** | 确保通信内容在传输中未被恶意或意外修改 | [[消息认证码]]、[[数字签名]] |
| **端点认证（End-Point Authentication）** | 通信双方能够确认对方的身份——对方确实是他/她声称的那个人 | [[端点认证]] |
| **运行安全（Operational Security）** | 保护组织网络免受攻击者入侵、植入蠕虫、获取机密、发动 DoS 攻击 | [[防火墙与入侵检测系统]] |

Alice 和 Bob 是安全领域的经典角色：Alice 是发送方，Bob 是接收方，Trudy 是入侵者（intruder）。Trudy 可以在信道上执行**窃听（eavesdropping）**和**修改、插入、删除消息**。这些能力使 Trudy 能够发动各种攻击：窃取密码和数据、冒充他人、劫持会话、拒绝服务等。安全通信的目标就是在 Trudy 拥有这些能力的情况下仍然保证上述四要素。

安全通信中的"Alice 和 Bob"可以是：人类用户（安全电子邮件、电子商务）、网络基础设施组件（DNS 服务器需要安全查询、路由守护进程需要安全交换路由信息）、网络管理实体等。

## 恶意软件

**恶意软件（malware）**是进入并破坏我们设备的恶意程序的总称。恶意软件可以通过网络传播，感染端系统，造成各种危害：删除文件、窃取个人信息（社会安全号、密码、信用卡号）、安装垃圾邮件服务器、记录按键，或将受感染设备编入**僵尸网络（botnet）**。僵尸网络由数千个类似的受感染设备组成，可被控制者用于发动分布式拒绝服务攻击或大规模发送垃圾邮件。

多数恶意软件是**自我复制（self-replicating）**的：一旦感染一台主机，就会试图从该主机通过因特网感染其他主机。自我复制的恶意软件可以呈指数速度扩散。常见的传播方式包括：

- **病毒（Virus）**：需要某种形式的用户交互才能感染设备。例如，用户点击了恶意电子邮件中的附件。
- **蠕虫（Worm）**：无需任何显式用户交互即可感染设备。蠕虫利用网络应用中的安全漏洞自动传播。

## 拒绝服务攻击

**拒绝服务攻击（Denial-of-Service, DoS 攻击）**使合法用户无法使用网络、主机或基础设施。Web 服务器、邮件服务器、DNS 服务器乃至机构网络都可能成为攻击目标。因特网 DoS 攻击极为常见，每年发生数千次。

大多数 DoS 攻击分为三类：

| 类型 | 方法 |
|------|------|
| **漏洞攻击** | 向目标主机上的漏洞应用或操作系统发送精心构造的报文，使其停止服务或崩溃 |
| **带宽泛洪** | 向目标主机发送大量分组，拥塞其接入链路，使合法流量无法到达 |
| **连接泛洪** | 在目标主机上创建大量半开或全开的 TCP 连接，使其无法接受合法连接 |

当攻击者使用多个受控源（即僵尸网络）向目标发动 DoS 攻击时，称为**分布式拒绝服务攻击（DDoS）**。DDoS 利用成千上万的受感染主机（僵尸）同时向目标发送流量，远比单一源攻击难以防御。

## 分组嗅探

许多网络环境使用**共享介质**（如 WiFi 或某些以太网配置），其中一台主机发送的分组可被范围内所有连接在共享介质上的主机接收到（即使目的地址不是自己）。在正常操作中，网络接口卡会丢弃目的地址不匹配的分组。但**分组嗅探器（packet sniffer）**可以记录每个经过的分组的副本，包括密码、电子邮件内容等敏感信息。

有线广播环境（如传统以太网 LAN）中也存在类似风险。解决嗅探问题需要**加密（encryption）**——即使嗅探器捕获了分组，加密的内容也无法被解读。

## IP 欺骗

攻击者可以将具有虚假源 IP 地址的分组注入因特网，这称为 **IP 欺骗（IP Spoofing）**。IP 欺骗使得追踪攻击来源变得困难，因为每个分组似乎都来自不同的（虚假的）源地址。IP 欺骗通常与其他攻击（如 DoS 攻击）结合使用。

## 端到端论证

面对上述安全威胁，应在协议栈的哪个层次部署安全防御？**端到端论证（end-to-end argument）**指出：当某种功能（如安全）可以同时在高层和低层实现时，应该在通信端点（即高层，如应用层）实现，而不是在通信路径的中间节点（低层）实现。这是因为：

1. 低层仅保护了部分路径的安全（如 WiFi 加密只保护无线段），而高层（端到端）加密保护了从源到目的地的全程数据
2. 低层无法了解最终应用的安全需求

然而，这并不意味着低层安全功能无用——低层加密可以防止分组嗅探（如 WiFi 的 WPA2），这些措施作为纵深防御的一层是有价值的。例如，用户在使用 Web 银行时，除了应用层的 TLS 加密，WiFi 链路的链路层加密也提供了额外的一层保护。
