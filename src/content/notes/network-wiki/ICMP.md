# ICMP

> 参考：Kurose §5.6

**因特网控制报文协议（Internet Control Message Protocol, ICMP）**被主机和路由器用于在网络层彼此通信。ICMP 最典型的用途是**差错报告**。例如，HTTP 会话中遇到的"Destination network unreachable"错误消息源于 ICMP——某个路由器无法找到到指定主机的路径时，该路由器创建并向主机发送一个 ICMP 消息指示错误。

ICMP 在架构上位于 IP **之上**——ICMP 消息作为 IP 有效载荷承载（就像 TCP 或 UDP 报文段一样），上层协议号为 **1**。

## ICMP 消息格式

ICMP 消息包含一个**类型（type）**字段和一个**编码（code）**字段，并包含导致 ICMP 消息生成的那个 IP 数据报的**首部和前 8 字节**（以便发送方确定哪个数据报导致了错误）。

## 常见 ICMP 消息类型

| 类型 | 编码 | 描述 |
|------|------|------|
| 0 | 0 | 回显应答（Echo Reply）——pong |
| 3 | 0 | 目的网络不可达 |
| 3 | 1 | 目的主机不可达 |
| 3 | 3 | 目的端口不可达 |
| 3 | 4 | 需要分片但 DF 置位（用于 PMTUD）|
| 5 | 0 | 重定向（Redirect）——告知主机有更好的下一跳 |
| 8 | 0 | 回显请求（Echo Request）——ping |
| 11 | 0 | TTL 过期 |

## Ping 程序

著名的 **ping** 程序向指定主机发送 ICMP **类型 8 编码 0** 报文（回显请求）。目的主机看到回显请求后，发送回 **类型 0 编码 0** ICMP 回显应答。大多数 TCP/IP 实现直接在操作系统中支持 ping 服务器——服务器不是一个进程。

## Traceroute 程序

**Traceroute** 使用 ICMP 消息实现路由追踪功能。工作原理：

1. 源主机发送一系列普通 IP 数据报到目的地，每个数据报承载一个带有**不可能 UDP 端口号**的 UDP 报文段
2. 第一个数据报的 TTL = 1，第二个 TTL = 2，第三个 TTL = 3……
3. 源也为每个数据报启动定时器
4. 当第 $n$ 个数据报到达第 $n$ 个路由器时，路由器观察到 TTL 刚过期，根据 IP 协议规则丢弃数据报并向源发送 ICMP **类型 11 编码 0** 警告消息（包含路由器名称和 IP 地址）
5. 源收到 ICMP 消息后获得往返时间和路由器信息
6. 最终有一个数据报到达目的主机。由于使用不可能端口号，目的主机向源返回**端口不可达** ICMP 消息（**类型 3 编码 3**）。收到此消息后，源知道不再需要发送探测分组

标准 Traceroute 程序实际为每个 TTL 发送**三个分组**，因此 Traceroute 输出为每个 TTL 提供三个结果。

## 路径 MTU 发现（PMTUD）

ICMP 在**路径 MTU 发现（Path MTU Discovery）**中起关键作用：源主机发送数据报时置 DF（Don't Fragment）标志，当路由器收到该数据报但出链路 MTU 小于数据报长度时，路由器丢弃数据报并返回 ICMP **类型 3 编码 4**（需要分片但 DF 置位）。源主机收到后减小发送的分组大小并重试，如此迭代直至找到整条路径上的最小 MTU。

## ICMP 重定向

当路由器收到数据报后发现存在比本路由器更接近目的地的下一跳路由器（位于同一子网）时，路由器向源发送 ICMP **类型 5 编码 0**（重定向）消息，告知源主机使用更好的下一跳。这使得源主机可以优化其路由表。

## ICMPv6

IPv6 的新版 ICMP（ICMPv6）定义在 RFC 4443 中，除了重新组织现有的 ICMP 类型和编码定义外，还添加了以下关键功能：

- **Packet Too Big**（类型 2）：数据报超出出链路 MTU 时发送，用于 IPv6 的 PMTUD（IPv6 中路由器不分片）
- **邻居发现（Neighbor Discovery, ND）**：ICMPv6 的邻居请求（类型 135）和邻居通告（类型 136）消息取代了 IPv4 中的 ARP，用于将 IPv6 地址解析为 MAC 地址。ICMPv6 路由器请求（类型 133）和路由器通告（类型 134）取代了 DHCPv4 中的部分功能。详见 [[IPv6邻居发现协议]]
