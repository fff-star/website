# 计算机网络与因特网概述

> 参考：Kurose §1.1

计算机网络与因特网概述是关于计算机网络的入门性介绍。本章回答两个基本问题：什么是因特网，以及什么是协议。围绕这两个问题，本章逐步展开对网络边缘、网络核心、时延与吞吐量、协议层次模型等主题的讨论，为后续章节提供概念框架。

## 什么是因特网

可以从两个互补的视角来回答这个问题。

### 具体构成视角

从硬件和软件组件的角度，因特网是一个互联全球数十亿计算设备的计算机网络。所有连接到因特网的设备称为**主机（host）**或**端系统（end system）**，它们通过**通信链路（communication link）**和**分组交换机（packet switch）**连接在一起。

端系统之间交换数据时，发送端将数据分段并添加首部字节，形成**分组（packet）**。分组通过网络中的交换机逐跳转发到目的地，在目的地重新组装为原始数据。分组从源到目的地经过的通信链路和分组交换机的序列称为**路径（route/path）**。

分组交换机主要有两类：用于网络核心的**路由器（router）**和用于接入网的**链路层交换机（link-layer switch）**。端系统通过**因特网服务提供商（ISP）**接入因特网。ISP 自身也是由分组交换机和通信链路组成的网络，低层 ISP 通过高层 ISP 互联，高层 ISP 之间也互相连接，最终形成「网络的网络」。

所有端系统、分组交换机和因特网的其他部件都运行着**协议（protocol）**，其中最重要的是**传输控制协议（TCP）**和**网际协议（IP）**，统称 TCP/IP。因特网标准由**因特网工程任务组（IETF）**制定，其标准文档称为 **RFC**（Request for Comments）。

### 服务描述视角

从服务的角度，因特网是为**分布式应用（distributed application）**提供通信服务的基础设施。分布式应用涉及多个端系统相互交换数据——应用运行在端系统上，而非网络核心的分组交换机中。分组交换机只负责将数据从源转发到目的地，不关心这些数据属于哪个应用。

端系统通过**套接字接口（socket interface）**向因特网基础设施请求数据交付服务。套接字接口规定了发送程序必须遵循的规则，类似于邮政服务要求寄信人必须将信装入信封、写明地址、贴邮票才能投递。因特网为应用提供多种运输服务选择，例如可靠的面向连接服务（TCP）和不可靠的无连接服务（UDP）。

## 协议

本章的另一核心概念是**协议（protocol）**：协议定义了通信实体之间交换的**消息格式**和**消息次序**，以及发送/接收消息或发生其他事件时采取的**动作**。因特网中所有活动——从网卡上比特流的传输到 Web 浏览器获取网页——都由协议控制。

以 Web 请求为例：浏览器首先向服务器发送 TCP 连接请求，服务器确认；浏览器随后发送 GET 报文指定要获取的页面；服务器返回该页面的内容。整个交互过程的每一步都遵循 HTTP 和 TCP 协议的规定。

学习计算机网络，本质上就是学习各种网络协议的**是什么**、**为什么**和**怎么做**。
