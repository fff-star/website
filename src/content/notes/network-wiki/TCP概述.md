# TCP 概述

> 参考：Kurose §3.5

**传输控制协议（Transmission Control Protocol, TCP）** 是因特网运输层中最重要、最复杂的协议。它为应用提供了**可靠的、面向连接的、全双工的字节流传输服务** 。

## TCP 的特点

TCP 具有以下关键特征：

| 特征 | 说明 |
|------|------|
| **面向连接** | 数据交换前需通过三次握手建立 TCP 连接 |
| **全双工** | 数据可同时在两个方向流动 |
| **点到点** | 一个发送方和一个接收方，不支持多播 |
| **可靠、有序** | 保证数据无差错、不丢失、不重复、按序交付 |
| **面向字节流** | 应用层数据被视为连续的字节流，无消息边界 |
| **流水线** | 使用滑动窗口机制，允许多个未确认报文段 |
| **流量控制** | 防止发送方淹没接收方 |
| **拥塞控制** | 防止发送方淹没网络 |

## TCP 连接

TCP 连接是**逻辑连接**——连接状态完全驻留在端系统中，中间路由器完全不知道 TCP 连接的存在。TCP 连接在两个端系统之间提供**全双工数据传输**：进程 A 到进程 B 的数据流与进程 B 到进程 A 的数据流可以同时存在，没有相互干扰。

TCP 连接由两个端系统的以下四元组唯一标识：

$$(\text{源IP地址}, \text{源端口号}, \text{目的IP地址}, \text{目的端口号})$$

这意味着同一个 IP 地址和端口号可以参与多个不同的 TCP 连接（只要其他参数不同）。

## TCP 报文段

应用层数据通过 TCP 连接传输的单位是**报文段（segment）**。TCP 从发送缓存中取出数据块（通常受限于**最大报文段长度 MSS**），为每个数据块添加 TCP 首部形成报文段，交给网络层。MSS 通常由本地最大链路层帧长度（即**最大传输单元 MTU**）决定——确保 TCP 报文段加上 TCP/IP 首部后适配单个链路层帧。以太网和 PPP 链路的常见 MSS 值为 **1460 字节**（MTU 1500 字节 − IP 首部 20 字节 − TCP 首部 20 字节）。

## TCP 可靠数据传输

TCP 在 IP 提供的不可靠尽力而为服务之上提供可靠数据传输。TCP 确保其接收缓存中提取的数据流是无损坏、无丢失、无重复且按序的字节流。TCP 使用了检验和、定时器、序号、确认号和滑动窗口的组合机制来实现这一目标。

## TCP 流量控制

TCP 的流量控制服务确保发送方不会溢出接收方的缓冲区。接收方在每个报文段中通告其接收窗口中可用的空闲缓冲区空间——`rwnd`（receive window）。发送方确保其未确认的数据量始终不超过 `rwnd`。

## TCP 连接管理

TCP 连接的建立需要三次握手（three-way handshake）：SYN → SYN-ACK → ACK。连接的拆除需要四次挥手（four-way handshake）：FIN → ACK → FIN → ACK。每个步骤中的序号和确认号精确地协调了两端的初始序号和状态转换。
