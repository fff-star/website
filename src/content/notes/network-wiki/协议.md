# 协议

> 参考：Kurose §1.1.3

协议（protocol）是计算机网络中通信实体之间交互的规则。精确的定义是：**协议定义了在两个或多个通信实体之间交换的消息格式和消息次序，以及发送和/或接收消息或发生其他事件时所采取的动作**。

协议是计算机网络的基石。因特网中所有涉及两个或多个远程通信实体的活动都由协议控制——从网卡之间导线上的比特流传输，到路由器的分组转发决策，再到浏览器向 Web 服务器请求网页。

## 人类类比

人类在日常生活中不断执行各种协议，这些类比有助于理解网络协议的本质。

### 询问时间

假设 A 想向 B 询问时间。典型交互如下：

1. A 说「你好」——发起通信的问候消息
2. B 回应「你好」——确认愿意通信
3. A 问「现在几点了？」——提出核心问题
4. B 回答「两点半」——提供所需信息

这个简单交互中，协议规定了特定的消息（问候、问题、回答）和特定的动作（先问候再提问）。B 的「你好」回应被隐式理解为可以继续对话的信号。如果 B 回应「别烦我！」或「我不会说中文」，协议就要求 A 不再继续询问——收到拒绝消息后停止通信，这是协议规定的动作。

如果对方不给出任何回应，在等待一定时间后，人们通常会放弃并向他人询问。这展示了另一个关键的协议概念：在给定时间内未收到响应时采取的动作（超时处理）。

### 课堂提问

教师讲课时，你感到困惑。教师停下来问「有什么问题吗？」（一条发送给所有学生的消息）。你举手（发送一条含蓄的消息）。教师点头微笑说「嗯……」（示意你提问）。你提出问题，教师听取并给出回答。

在这个交互中，消息的发送和接收以及约定俗成的动作（先举手再被点名再提问）构成了课堂提问的「协议」。同样——如果两人运行着不同的协议（比如一人彬彬有礼、另一人粗鲁无礼），协议就无法互操作，无法完成有意义的交流。

### 类比的启示

这些人类类比揭示了协议的三个关键维度：

1. **消息格式**：问候语、问题、回答各自有不同的形式
2. **消息次序**：必须先问候、确认对方愿意通信，然后才能提问
3. **动作**：收到拒绝后停止、超时后放弃、收到回答后表示感谢等

## 网络协议

网络协议与人类协议相同，区别仅在于交换消息和采取动作的实体是硬件或软件组件。

### Web 请求协议交互示例

当用户在浏览器地址栏输入 URL 并按下回车时，发生以下协议交互：

1. 用户的计算机向 Web 服务器发送一个 **TCP 连接请求报文**
2. Web 服务器收到请求，返回一个 **TCP 连接确认报文**
3. 用户的计算机知道现在可以请求 Web 文档了，于是发送 **GET 报文**，其中包含要获取的页面路径
4. Web 服务器返回该页面（文件）的内容

整个过程的每一步都由协议规定。TCP 协议控制着步骤 1 和 2（三次握手中的两步），HTTP 协议控制着步骤 3 和 4（请求和响应）。

### 因特网中协议的广泛使用

协议在因特网中无处不在：

- 两台物理连接的计算机的网卡上，**硬件实现的协议**控制着导线上的比特流
- 端系统中的**拥塞控制协议**控制着分组传输的速率，防止网络过载
- 路由器中的**路由协议**决定每个分组从源到目的地的转发路径
- **HTTP** 控制 Web 浏览器和服务器之间的消息交换
- **SMTP** 控制邮件服务器之间的电子邮件传输
- **DNS** 控制主机名到 IP 地址的查询和响应

## 协议的三要素

| 要素 | 含义 | HTTP GET 示例 |
|------|------|--------------|
| 语法（消息格式） | 消息的结构定义，包括字段、长度、编码 | `GET /index.html HTTP/1.1\r\nHost: www.example.com\r\n\r\n` |
| 语义（动作） | 每条消息的含义以及收到后应执行的操作 | 收到 `200 OK` 渲染页面；收到 `404 Not Found` 显示错误 |
| 时序（次序） | 消息发送和接收的先后顺序 | 先三次握手建立 TCP 连接 → 再发送 GET 请求 → 等待响应 |

## 协议与标准化

要使人可以创建互操作的系统，必须就每个协议的功能达成共识。这就是标准存在的意义。因特网协议的标准由 IETF 以 RFC 文档的形式发布。此外，IEEE 802 委员会定义了以太网和 WiFi 等链路层标准。标准化确保了不同厂商的设备可以无缝协作。

## 学习协议的方法

学习计算机网络等同于学习网络协议。对每个协议，应该问三个问题：

1. **是什么（What）**：协议定义了怎样的消息格式和交互序列？
2. **为什么（Why）**：为什么选择这种设计？有何取舍？
3. **怎么做（How）**：协议在设备和软件中如何实现？
