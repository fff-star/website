# IPv6 邻居发现协议（NDP）

> 参考：Kurose §4.3.6；RFC 4861

**邻居发现协议（Neighbor Discovery Protocol, NDP）**是 IPv6 协议族的一部分，基于 **ICMPv6** 实现。它替代了 IPv4 中多项分散的功能——ARP、DHCP 的网关发现、ICMP 重定向——并将其统一到一组 ICMPv6 消息中。

## NDP 的五大消息类型

| ICMPv6 类型 | 名称 | 方向 | 作用 |
|:---:|:---|:---|:---|
| 133 | **RS**（Router Solicitation） | 主机 → 路由器 | 「子网里有路由器吗？请立即回复。」 |
| 134 | **RA**（Router Advertisement） | 路由器 → 主机 | 「我是路由器。前缀是xxx，网关地址是yyy。」 |
| 135 | **NS**（Neighbor Solicitation） | 主机 → 主机 | 「IP 是 xxx 的，你的 MAC 地址是什么？」 |
| 136 | **NA**（Neighbor Advertisement） | 主机 → 主机 | 「IP 是 xxx，我的 MAC 地址是 yyy。」 |
| 137 | **Redirect** | 路由器 → 主机 | 「更好的下一跳在那里，别走我这了。」 |

所有 NDP 消息使用 IPv6 多播而非广播——消除了 IPv4 中 ARP 广播泛滥的问题。

## RS 与 RA：路由器发现与自配置

这是 NDP 为 SLAAC 和 DHCPv6 提供的基础设施。RA 携带了主机自配置所需的全部信息。

### RA 的触发方式

RA 有两种发送方式：

**方式一：周期性主动发送（Unsolicited RA）**

路由器定期向多播地址 `ff02::1`（链路内所有 IPv6 节点）**定时广播** RA。默认间隔通常为 **200 至 600 秒**，带有小幅随机抖动以防止相邻路由器同时发送导致冲突。

**方式二：RS 触发即时响应（Solicited RA）**

主机刚接入网络时，不会等待下一个周期性 RA——它立即向多播地址 `ff02::2`（链路内所有路由器）发送 **Router Solicitation (RS)**，催促路由器回复。路由器收到 RS 后，**单播** RA 直接回复请求主机。整个过程在毫秒级完成——插上网线不到一秒就拿到前缀和网关。

```
主机（刚接入）                    路由器
      │                              │
      │── RS ────────────────────▶  │  到 ff02::2（所有路由器）
      │   "有路由器吗？给我配置！"      │
      │                              │
      │◀─ RA ─────────────────────  │  单播回复
      │   "前缀2001:db8::/64         │
      │    网关=fe80::1              │
      │    M=0 O=1 A=1              │
      │    MTU=1500"                │
```

### RA 携带的信息

| 字段 | 用途 |
|:---|:---|
| **网络前缀**（如 `2001:db8::/64`） | SLAAC 主机拼接地址的前 64 位 |
| **M/O/A 标志位** | `M`=有状态 DHCPv6、`O`=无状态 DHCPv6、`A`=前缀可用于 SLAAC |
| **路由器链路本地地址** | 主机将其设为**默认网关** |
| **跳限制（Hop Limit）** | 主机发送数据报应使用的 TTL 值 |
| **MTU** | 链路的最大传输单元 |
| **可达时间** | 邻居被认为是可达的时间 |
| **重传定时器** | 邻居请求的重传间隔 |
| **路由器生存期** | 0 表示这不是默认网关；非零表示网关有效期 |
| **前缀有效期** | 有效生存期和首选生存期 |

## NS 与 NA：取代 ARP

在 IPv4 中，主机通过 ARP（广播）解析邻居的 MAC 地址。IPv6 用 NS/NA 完成同样的事情，但使用多播而非广播——只有目标地址对应的多播组的节点才会收到 NS，不会打扰子网内所有主机。

### 工作过程

```
主机A（想和 2001:db8::b 通信，不知其 MAC）:
  → 发 NS 到 2001:db8::b 对应的恳求节点多播地址 (solicited-node multicast)
  → "IP 是 2001:db8::b 的，你的 MAC 是什么？"

主机B:
  → 收到 NS（因为自己是那个多播组成员）
  → 单播 NA 回复给 A
  → "IP 是 2001:db8::b，我的 MAC 是 bb:bb:bb:bb:bb:bb"
```

对比 IPv4 ARP：ARP 广播到 `FF-FF-FF-FF-FF-FF`，子网内所有主机都必须处理。IPv6 NS 只发送给与该 IP 地址关联的多播组——无关主机完全不受打扰。

## DAD：利用 NS 做地址冲突检测

SLAAC 生成的地址在启用前必须确认没人占用，这个过程称为 **DAD（Duplicate Address Detection，重复地址检测）**。DAD 本身并不是独立协议——它复用 NS 消息：

1. 主机向自己即将使用的地址发送 **NS**
2. 如果收到 **NA** 回复——说明已被占用，这个地址不能使用
3. 如果超时（默认 1 秒）未收到任何回复——地址可用，安全启用

## NDP 与 IPv4 的对应关系

| IPv4 功能 | IPv4 实现 | IPv6 NDP 替代 |
|:---|:---|:---|
| 地址解析（IP → MAC） | ARP（独立协议，广播） | NS/NA（ICMPv6 类型 135/136，多播） |
| 路由器发现 | DHCP 提供默认网关 | RA（ICMPv6 类型 134） |
| 主机催促路由器 | 无对应机制（只能等 DHCP） | RS（ICMPv6 类型 133） |
| 重复地址检测 | 无标准机制（Gratuitous ARP 非正式） | DAD（NS/NA 复用） |
| 重定向 | ICMP 类型 5 | ICMPv6 类型 137 |
