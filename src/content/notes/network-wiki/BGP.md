# BGP

> 参考：Kurose §5.4

## BGP 解决什么问题？

已经知道，一个 AS 内部用 OSPF 管路由——洪泛 LSA、跑 Dijkstra、算出到 AS 内每个子网的最短路径。但**因特网有几十万个 AS**，不能把全世界的路由器放在一个 OSPF 域里洪泛。

AS 之间怎么互相告诉「我这里有这些 IP 前缀可以到达」？这就是 **BGP（Border Gateway Protocol，边界网关协议）**的职责。

它与 OSPF 的根本区别：

| | OSPF | BGP |
|:---|:---|:---|
| 作用域 | AS 内部 | **AS 之间** |
| 目标 | 找最短路径 | **在尊重商业策略的前提下找到可行路径** |
| 广播什么 | 链路状态（连着谁、代价多少） | **可达前缀 + AS 路径** |
| 谁在跑 | AS 内所有路由器 | **边界路由器**（AS 之间的网关） |

## 核心机制：通告前缀 + 携带路径

BGP 不关心链路代价——它交换的是**「某个 IP 前缀可以通过怎样的 AS 路径到达」**。

假设 AS3 拥有前缀 `10.0.3.0/24`：

```
 AS1 ←──→ AS2 ←──→ AS3
                        │
                    10.0.3.0/24

1. AS3 的边界路由器向 AS2 通告:
   "10.0.3.0/24 可以到达，路径: [AS3]"

2. AS2 收到后，在前面加上自己的 ASN，向 AS1 通告:
   "10.0.3.0/24 可以到达，路径: [AS2, AS3]"

3. AS1 收到后知道: 去 10.0.3.0/24 → 经过 AS2 → AS3
```

**AS-PATH 就是通告走过的一串 ASN 列表。** 它干两件事：

- **防环路**：如果路由器收到一条通告，AS-PATH 里已经包含自己的 ASN——说明兜回来了，直接丢弃
- **路径长度比较**：多条路由中，AS-PATH 短的优先（类比跳数，粗粒度）

这就是 BGP 被称为**路径向量（Path Vector）协议**的原因——它在距离向量的基础上附加了完整路径，解决了 DV 算法中计数到无穷的问题。

## eBGP 与 iBGP：谁和谁建连接

BGP 的连接在路由器对之间建立（TCP 179，半永久维持），按连接的对象分两种：

```
                     eBGP                          eBGP
  [AS1] ─────────────────── [AS2] ─────────────────── [AS3]
    │      跨 AS 的连接         │      跨 AS 的连接         │
    │                          │                          │
    ├── iBGP ──┤         ├── iBGP ──┤         ├── iBGP ──┤
   R1a ←──→ R1b        R2a ←──→ R2b        R3a ←──→ R3b
    AS1 内部全互联          AS2 内部全互联          AS3 内部全互联
```

- **eBGP**：跨越 AS 边界，连接两个不同 AS 的边界路由器
- **iBGP**：AS 内部，连接同一 AS 内的所有 BGP 路由器

**为什么需要 iBGP？** 一个 AS 可能有多个边界路由器（AS2 有 R2a 连 AS1、R2b 连 AS3）。R2a 从 AS1 学到某前缀可达，但 AS2 内部的其他边界路由器 R2b 不知道——需要通过 iBGP 把这个信息**转发给同 AS 内的所有兄弟**，这样 AS2 的所有出口路由器都有一致的外部路由信息。

iBGP 有一个特殊规则：**从 iBGP 学到的路由不能再通过 iBGP 转发**（防环路）。这意味着 AS 内的所有 BGP 路由器必须**两两之间建立 iBGP 连接**——全互联网格（full mesh）。当 AS 内有几百台路由器时，$O(n^2)$ 的连接数无法承受。解决方案是**路由反射器（Route Reflector）**——指定几台核心路由器为 RR，其余路由器只连 RR。RR 可以将从一台路由器学到的路由「反射」给其他路由器，打破不转发 iBGP 的限制。

## 到达外部前缀：NEXT-HOP 怎么用

BGP 路由携带的 **NEXT-HOP** 属性不是本 AS 内路由器的 IP，而是**通告方的 eBGP 边界路由器在外侧链路上的接口 IP**。

以 AS2 向 AS1 通告 `10.0.3.0/24` 为例：

```
         AS1                               AS2
   R1a ────────────── 2a ──── ... ──── 2c ────────────── 3c (AS3)
        直接相连的链路                      拥有 10.0.3.0/24

通告的内容:
  前缀: 10.0.3.0/24
  AS-PATH: [AS2, AS3]
  NEXT-HOP: 2a 在 AS1-AS2 链路上的接口 IP
```

R1a 收到后查 OSPF 转发表：NEXT-HOP 的这个 IP 在 AS1-AS2 链路上，通过本路由器的 eBGP 接口可达。于是 R1a 把 `10.0.3.0/24` 写入转发表，下一跳设为那条链路上 R2a 的接口。

**NEXT-HOP 是 BGP 和 IGP 的对接点**：BGP 告诉你「这个前缀从哪个入口进这个 AS」，而 IGP（OSPF）告诉你「在那个入口的方向上，下一跳路由器是谁」。

## 路由选择：不是最短路径，是策略优先

BGP 面对一个前缀可能收到多条路径（从不同邻居、不同 eBGP 连接），需要选一条。选路规则按优先级从高到低：

### 1. 本地偏好（LOCAL_PREF）——策略第一

最高优先级。完全由**本 AS 网络管理员手动设置**，不依赖任何自动度量。

> AS1 通过两条链路连接 AS2（链路 A 和链路 B）。管理员想让**所有出站流量**走链路 A，就在链路 A 收到的所有路由上打上 LOCAL_PREF=200，链路 B 打上 LOCAL_PREF=100。BGP 永远选 LOCAL_PREF 高的，于是流量全走 A。

这是 BGP 与 OSPF 最本质的区别：**最短路径不一定被选，策略说了算。**

### 2. 最短 AS-PATH——粗粒度的距离度量

LOCAL_PREF 相同的情况下，选 AS-PATH 最短的。这是 BGP 里唯一类似「最短路径」的地方，但粒度是整个 AS 而非单条链路。

### 3. 热土豆路由（Hot Potato）——尽快脱手

如果 AS-PATH 也相同（即从多个出口可以到达同一个下游 AS），选**离 NEXT-HOP 最近的出口**——即 IGP（OSPF）代价最小的出口。

```
          AS1
    R1a ──┬── R1c ──────── AS2
          │
    R1b ──┴── R1d ──────── AS2（另一条链路）

AS1 从 R1c 和 R1d 都收到了去 AS2 前缀的通告，AS-PATH 相同。
R1a 查自己的 OSPF 表：去 R1c 代价=5，去 R1d 代价=20 → 选 R1c。
```

这就是「热土豆」的含义——**把分组尽快扔出本 AS，不关心它在后续 AS 里走多远。** 这是一种自私策略：出口离自己越近越好，别人的网络别人操心。

### 4. MED——请对端 AS 选择特定入口

如果前三个条件都相同，看 **MED（Multi-Exit Discriminator）**。MED 是本 AS 通告给**相邻 AS**的一个建议值，告诉对方「如果你有多个入口，建议走 MED 小的那个」。MED 控制的是**入站流量**（对方怎么进来）。

### 5. Router ID 兜底

全相同选 Router ID 最小的。

## 路由策略：商业关系决定通告内容

BGP 不是「我知道的路就告诉所有人」——通告内容受商业关系约束：

| 关系 | 含义 | 通告策略 |
|:---|:---|:---|
| **客户（Customer）** | 付钱买带宽 | 收到的所有路由都通告给客户 |
| **对等（Peer）** | 互相免费交换流量 | **只通告自己和自己的客户的路由**，不通告来自其他对等方或上游的路由 |
| **上游（Provider）** | 卖带宽给它 | 收到的所有路由都通告给上游 |

关键在于**无免费中转**：两个对等 ISP（如中国电信和中国联通）互相只通告「我的网络和我的客户」，不会通告「我还能途经我到达另一个 AS」。如果允许免费中转，ISP A 就可以通过 ISP B 的骨干网到达 ISP C 而不付钱——ISP B 的骨干带宽被白嫖。

这种策略通过**选择性通告**实现——路由器有到某前缀的路由，但对特定邻居不发出这条 UPDATE。

## BGP 消息类型

BGP 对等体之间（TCP 179）交换四种消息：

| 消息 | 作用 |
|:---|:---|
| **OPEN** | 建立会话，协商 ASN、版本、Hold Time |
| **UPDATE** | 通告新路由或撤销旧路由（核心消息） |
| **KEEPALIVE** | 心跳，默认 30 秒一次，超时则断开会话 |
| **NOTIFICATION** | 报错后关闭会话 |

## 安全：为什么路由会被劫持

BGP 设计之初没有验证机制——任何 AS 可以通告任何前缀。攻击者（或配置失误的 ISP）宣称自己拥有某个不属于它的前缀，流量就会被重定向。2008 年巴基斯坦电信为封锁 YouTube，意外通告了一条更具体的 YouTube 前缀，导致全球 YouTube 瘫痪约两小时。

**RPKI（Resource Public Key Infrastructure）** 事后补了一部分安全：IP 地址持有者签署 **ROA（Route Origin Authorization）**，声明「只有 AS X 有权通告前缀 Y」。路由器验证 BGP 通告中的 (ASN, 前缀) 是否匹配有效 ROA，不匹配则丢弃或降级。但 RPKI 只验证**源 AS**，不能防御中间 AS 篡改 AS-PATH。

## 为什么域内域外要分开？

| | OSPF（域内） | BGP（域间） |
|:---|:---|:---|
| 策略 | 不重要——同一个管理员 | **最重要**——谁的流量走谁的网、谁付钱 |
| 规模 | 可分层解决（区域） | 必须处理几十万前缀 |
| 性能 | 追求最短路径 | 策略优先，路径存在即可 |
| 拓扑暴露 | AS 内部可见 | AS 内部拓扑对外**隐藏** |
