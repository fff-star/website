# 运输层概述

> 参考：Kurose §3.1

运输层位于应用层和网络层之间，是分层网络体系结构的核心部分。它的关键作用是**将网络层提供的"主机到主机"交付服务扩展为运行在不同主机上的应用进程之间的"进程到进程"交付服务**。

## 运输层与网络层的关系

网络层提供了**主机到主机**的逻辑通信——它将分组从源主机逻辑地传送到目的主机。运输层则提供了**进程到进程**的逻辑通信——它将报文从源主机的某个应用进程传送到目的主机的某个应用进程。

用一个类比来说明：两家分别有 12 个孩子（对应 12 个应用进程），两家之间通过邮政服务（对应网络层）交换信件。每一家指定一个孩子负责收发信件——Ann 每天早上在门口收集所有寄来的信并分发给其他孩子（对应运输层的多路分解），每天晚上收集所有要寄出的信交给邮政人员（对应运输层的多路复用）。邮政服务只负责两家之间的信件运输（主机到主机），而 Ann 提供的服务是孩子之间的信件收发（进程到进程）。

## 运输层协议

因特网提供了两种运输层协议：

（注：新近的 [[QUIC]] 协议在 UDP 之上实现了完整的运输层功能——可靠传输、拥塞控制、安全加密——可视为在应用层运行的第三种运输协议。本概述聚焦传统的 TCP/UDP。）

| | TCP | UDP |
|---|-----|-----|
| 服务模型 | 面向连接、可靠 | 无连接、不可靠 |
| 交付保证 | 保证字节流正确、按序到达（[[TCP可靠数据传输|可靠传输]]） | 尽力而为交付 |
| 拥塞控制 | 有（[[TCP拥塞控制|拥塞控制]]） | 无 |
| 流量控制 | 有（[[TCP流量控制|流量控制]]） | 无 |
| 连接建立 | 需[[TCP连接管理|三次握手]] | 无连接 |

网络层协议（IP）的服务模型是**尽力而为（best-effort）**——它不保证分组不丢失、不保证分组按序到达、不保证分组中数据的完整性。IP 被称为**不可靠服务（unreliable service）**。运输层的工作正是在 IP 提供的不可靠主机到主机服务之上，为应用提供具有不同可靠性、吞吐量和定时保证的传输服务。

## 运输层在网络中的位置

端系统中的运输层协议负责将应用层报文从进程移动到网络边缘（即网络层），并在接收端执行相反操作。值得注意的是，**路由器和链路层交换机不处理运输层协议**——它们只处理网络层及以下的内容。中间路由器只检查网络层字段（如 IP 首部），不会触及封装在网络层数据报中的运输层报文段。这是分层体系结构的关键设计原则：只有端系统使用运输层协议。

然而，某些网络设备会故意违背这一原则：例如 [[NAT]] 必须重写运输层端口号才能让多台私网主机共用同一个公网 IP。这种对分层原则的破坏是 IPv4 地址枯竭下的工程妥协，也带来了端到端原则被削弱等副作用。
